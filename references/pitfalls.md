# Common Pitfalls

1. **Editing generated symlinks directly.** `auth0_flutter/ios/Classes`, `auth0_flutter/macos/Classes`, and `auth0_flutter/darwin/Classes` are symlinks generated by `scripts/generate-symlinks.sh` from the canonical `darwin/auth0_flutter/Sources/auth0_flutter/` tree. Edits made directly to the symlinked paths will be silently discarded (or diverge) the next time the script runs, and CI's `check-symlinks` workflow will fail the PR.
2. **Missing `example/.env`.** `auth0_flutter analyze`/`test` read Windows/desktop/mobile constants that depend on `example/.env` existing; CI always copies it from `example/.env.example` first (`cp` on macOS/Linux, `Copy-Item` on Windows runners) — do the same locally before running analyze/test.
3. **Forgetting to regenerate mocks.** Adding or changing a `@GenerateMocks([...])` annotation without re-running `build_runner` leaves a stale `*.mocks.dart` that either fails to compile or mocks the wrong shape.
4. **Breaking the web/non-web split.** Code using `dart:js_interop` must stay behind the `_real.dart`/`_stub.dart` conditional-import split (see `auth0_flutter/lib/src/web/`) — importing JS interop directly into a shared file breaks compilation on Android/iOS/macOS/Windows.
5. **Version drift between the two packages.** `auth0_flutter` and `auth0_flutter_platform_interface` are published and versioned together; bumping one's `pubspec.yaml` version without the other (and without updating the `dependency_overrides`/version constraint in `auth0_flutter/pubspec.yaml`) breaks the federated-plugin contract.
